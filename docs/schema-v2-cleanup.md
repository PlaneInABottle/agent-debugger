# Schema v2 Breaking Cleanup — Implementation Plan

## Problem and Success Criteria
- Dual identity (`observedTarget` flat + `targetIdentity` layered) and version-less sidecars force null-tolerant legacy paths on every read; old session dirs silently behave as current.
- Success: single layered `targetIdentity` everywhere; every sidecar carries `schemaVersion:2`; old dirs are rejected with actionable errors except safe `close`/`status`; `close` can still clean an old dir; `status` never crashes a mixed listing; full gates green on v2 only.

## Approach
Smallest viable breaking design; no migration framework, no dual-schema in final tree, no `meta.json` consolidation.

**V2 sidecar contracts (all JSON objects, atomic tmp+rename in same dir, including `setup_bridge` `lang.json`/`stops.json` writes which become tmp+rename instead of direct writes):**
- `lang.json`: `{"lang":"py|node|java|browser","schemaVersion":2}` (current file is already an object — additive field only).
- `stops.json`: existing intent fields + `"schemaVersion":2`. `target` summary stays (spawn-derived display); `requestedTarget` stays (endpoint+flags, never an observation).
- `session.json` (bridge-owned): existing `name/kind/port/stopped/lastStop/updatedAt/…` + `"schemaVersion":2` + `"targetIdentity":{debuggee,endpoint,adapter}`. No `observedTarget` key in v2 (absent, not null).
- `error.json` (bridge-owned, CLI-read): `{"schemaVersion":2,"error":"…","phase":"transport|config"}`. Every early writer emits all three keys: py `pybridge.py` `setupErrorPayload` + `Usage`/`ConfigErr`/`BridgeErr` paths, node `nodebridge.js` `setupErrorPayload` + parse/`Usage` paths, browser `browserbridge.js` `setupErrorPayload` + parse paths, java `BridgeCli.java` parse-error path + `BridgeSession`/`BridgeProto` setup-error writes. Ordering note: `setup_bridge` writes v2 `lang.json`/`stops.json` before the bridge spawns, so by the time the CLI wait loop can observe `error.json`, the spawn-dir markers are already v2. Strict action: a present parseable `error.json` with `schemaVersion!=2` or missing/invalid `phase` → `corrupt setup error file in '<name>' (schemaVersion/phase); close and retry` (internal, never transport-diagnosed). Absent/unparseable file (or parseable JSON without an `error` string) keeps today's transport fallback.
- Package version `0.2.0` (`Cargo.toml`; `Cargo.lock` entry updates automatically via build, no manual edit); `status.version` follows automatically.

**Seed identity (replaces flat observed):** new Rust `seed_target_identity(&Target) -> Value` builds layered roles directly, redacted+capped with existing `redact_argv`/identity caps:
- launch (py/node/java): `debuggee {kind:process, executable, argv(redacted), cwd, source:"launcher-args", confidence:"unavailable", observedAt, unavailable:[{field:"pid", reason:"not protocol-confirmed (launcher args only); protocol event upgrades debuggee"}]}` (`pid:null`; the claimed command line is carried but confidence stays `unavailable` — launcher truth is not OS-corroborated identity). `endpoint {confidence:"unavailable"+reason}`, `adapter {name, confidence:"unavailable"+reason}`. Do not invent a `"launcher-args"` confidence value; `source` carries provenance, `confidence` stays in the existing `os-corroborated|protocol-confirmed|unavailable` vocabulary. The bridge's later protocol event upgrades `debuggee` to `protocol-confirmed`.
- attach (py/node/java): `debuggee {pid:null, confidence:"unavailable"+reason}`, `endpoint {host, port, ownerPid?, executable?, argv?(redacted), cwd?, source, confidence:os-corroborated|unavailable, observedAt}`, `adapter {confidence:"unavailable"}` (no debugpy-name guessing in seed; bridge confirms). Built from existing `port_lookup`/`normalize_attach_host` — no new OS mechanism.
- browser attach: seed `null`; browser builds own tab identity from `/json/list` (existing `buildObservedTab` path, renamed output).
- CLI passes seed as `--target-identity <json>` (replaces `--observed-target`/`--observed-hint`), inserted before `--` exactly like the current flags so program args after `--` are never swallowed. Malformed/missing seed on the bridge side → layered all-unavailable identity, never a spawn failure. Browser accepts the flag and ignores it (builds own).

**Old-dir detection (single helper, e.g. `require_schema_v2(dir)`):** old iff `lang.json` OR `stops.json` is missing/corrupt/lacks `schemaVersion==2`. CLI-owned files gate (avoids TOCTOU on bridge-owned `session.json`). `error.json` version never gates by itself (file-absence fallback above applies).
- Gated (exact list, gate after `check_name`/`check_dir_real`, before lang/port routing): all `forward_target` commands (`continue`, `wait`, `capture`, `step`, `stack`, `threads`, `vars`, `eval` per `src/main.rs:153-282`), all `forward` commands (`reload`, bare `breaks` list, `logs` per `src/main.rs:212-290` — `logs` gets no read-only exemption, see below), `cmd_targets`/`cmd_targets_in`, `cmd_context_target`, `cmd_breaks_add`/`remove`/`clear`. Exempt: `doctor`, `status`, `close`, spawn-create (`start`/`attach` creating the dir). Gate error: `bail!("unsupported session '{name}' (schema v1; close it and recreate)")`.
- `close`: no version gate ever — including an old live bridge still speaking the old protocol. `close` handlers are version-agnostic framed `{"cmd":"close"}` in every bridge (py `pybridge.py:4279`, node `nodebridge.js:3682+3791` via `CloseSession`, browser `browserbridge.js:2310+2392` via `CloseSession`, java `BridgeSession.java:1251+1077,1208` via `CloseSession`; framing is `Content-Length` JSON per `src/dap.rs:3-4`, `src/client.rs:12-15`). Read `port` from old `session.json` if present (same field), send close, run the existing 65s queued-close + 15s port-death check, then `remove_dir_all`. Never refuses cleanup. Upgrade note: `cargo install --path .` updates CLI + adapters together, but a still-running old bridge process stays old code until closed; `close` uses only `port` + generic close frame, so this is a non-issue.
- `status`: no gate, never errors a row, sorted by `name` as today. Exact row contract — v2 keeps every existing key, drops `observedTarget`, adds three keys:
  - current row: `{name, lang, kind, port, alive, stopped, lastStop, updatedAt, armed, target, requestedTarget, targetIdentity, stale:false, unsupported:false, hint:null}`. No `observedTarget` key.
  - old/unsupported row: same keys, `stale:true, unsupported:true, hint:"close '<name>' and recreate (unsupported schema v1)"`, values: `lang` from `lang.json:lang` string else `"unknown"`; `port` numeric-u16 else `0`; `alive` TCP probe iff port nonzero else `false`; `kind`/`stopped`/`lastStop`/`updatedAt` from parseable `session.json` else `null`; `armed`/`target`/`requestedTarget` from parseable `stops.json` else `armed:null, target:null, requestedTarget:null`; `targetIdentity` valid layered object else `null` (never flat, never promoted). No `observedTarget` key in either row.
  - boundary cases: v2 markers + absent `session.json` = current startup row (`alive:false, unsupported:false, stale:false`); present `session.json` lacking `schemaVersion==2` = old/unsupported even when `lang`/`stops` are v2 (bug → stale, never current).
- `spawn` same-name policy (today bails whenever `session.json` exists): v2 keeps that bail verbatim for v2-present dirs (`already exists (close it first)`), live or dead — no auto-reclaim of current sessions. Intentional one-time legacy exception only: a `session.json`-present OLD dir is reclaimed iff proven dead — parseable `session.json` with numeric nonzero `port` AND `daemon_alive_in==false` (double TCP fail + no recent publish). Corrupt/missing/unparseable/zero port, or anything less than proven-dead → `bail("unsupported session '{name}' (schema v1; close it first)")`. `session.json`-absent leftovers (incl. legacy) are still cleared as today. Never delete or kill while an old daemon may be live.
- Collision scan (fail-safe upgrade rule, global scan runs while the endpoint guard is held): endpoint locks still protect concurrent v2-vs-v2 attaches, but a pre-existing live v1 owner may be invisible to an endpoint match. Keep two distinct predicates: `attach_exclusive` (known `py|node|java` only, browser never collides — unchanged) for the endpoint-matched owner scan; and a wider global-legacy predicate (exclusive langs + unknown/missing lang fail-closed as exclusive; browser exempt) for the legacy-live scan. Before any v2 `attach` of an exclusive lang: (a) endpoint-matched scan first — an old dir with numeric parseable `requestedTarget` endpoint equal to the new endpoint (normalized host + port) reports that owner with `unavailable_identity(reason)` (zero pids) and `endpoint-already-attached`; (b) then the global scan — any remaining live old dir matching the global-legacy predicate blocks with `unsupported live legacy session(s) '<sorted names>'; close them first and retry` (new diagnosis code, e.g. `unsupported-legacy-live`, layered all-unavailable identity, no endpoint claim). Never risk a second client onto a possibly-shared target.
- Read-only old sessions: no `logs`-command exemption. Old sessions are `status`-visible then `close`-only; the `logs` gate stays. Rationale: an old bridge's `logs` framing is compat-uncertain and not worth certifying. If log lines matter, copy `logs.jsonl` aside manually before `close` (documented in `current-contract.md`, not a code path).

**`observedTarget` removal surface:** Rust `SpawnSpec.observed/observed_hint`, `cached_observed`, `launch_observed`/`attach_observed` (replaced by seed builder), `owner legacy map` (`identity_from_legacy_observed` + legacy branch in `owner_target_identity` → collapse to `unavailable_identity`), `intent_endpoint` `"target"` fallback (keep `requestedTarget` only), dead `normalize_target_for_lang`, bridge `--observed-target`/`--observed-hint` argv + `Config.observed_target/observedHint` + publish `observedTarget` keys + compat shims (`nodebridge.js:3866-3870`, `browserbridge.js:2462-2466` equivalents), `status`/`context`/`targets` (incl. singular `observed` key in `cmd_targets_in` roster)/spawn-response `observedTarget`/`observed` keys, tests + `SKILL.md` + docs references. Rename `cap_observed` iff its identity semantics change (it currently caps the flat shape; the layered cap keeps the same limits but the name must not lie — `cap_identity` if touched). `requestedTarget`, layered `targetIdentity`, `BridgeFailure`/envelope shape, aliases, milestone tests preserved. Note: `SKILL.md`'s legacy-mapping guidance for collisions goes stale the moment M1 collapses the map — refresh it in M2 (or the single default commit), never leave the stale procedure documented.

## Risks and Rollback
- `close` over-refuses old dir → user locked out: mitigation is no-version-gate `close` with explicit old live/dead cases; rollback is `close` path revert.
- `status` row shape breaks agent parsing: keep all current keys, add only `stale`/`unsupported`/`hint`; marker-less bridge output renders stale, never current; rollback row addition only.
- Seed confidence wording misread as protocol proof: launch `debuggee` is `source:"launcher-args"` + `confidence:"unavailable"` with explicit reason (protocol event upgrades it); review checks wording.
- Second-client risk from invisible v1 owner: mitigated by global live-legacy scan + `unsupported-legacy-live` block; endpoint lock alone is insufficient and is not relied on for pre-existing dirs.
- Rollback: one commit by default (two only if safely splittable); revert restores v1 readers (v2 test dirs are disposable); no data migration to undo.
