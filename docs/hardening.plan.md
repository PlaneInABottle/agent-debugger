## Approach
Smallest viable hardening in 3 milestones, same implementer session, no implementation code in this plan.

- M1 fixes crash-safety/lifecycle honesty with `continue`-not-`?`, corrupt-preservation, and JS exit discipline. All deterministic, local, no lock redesign.
- M2 fixes shared concurrency/framing at the entry points (real `serveLoop`/`serve()` paths, real gate discipline, shared negative fixtures). Reproduce py race before patch; do not merely add stale recheck. Strict parity is intentionally breaking for lenient senders (allowed: valuable correctness fix).
- M3 implements the decided provisioning guard (per-adapter `try_lock` files, fixed `node→browser` order, 200s/20ms bound, inode retained) + decided fail-closed `agent_home()` (no `/tmp` fallback) + honest `doctor`/`rust-version = "1.89"` + CI wiring to `run_gates.sh --unit` with decided pins. `urls` and installer checksums default to accurate deferred docs (unbounded per-session risk note; verification against already-published `.sha256`/`SHA256SUMS.txt`), not speculative LRU or silent install breakage.
- Alternatives rejected: full language-bridge rewrite, generic repository/service layers, arbitrary LRU eviction of script identities, new `close --force` with PID kill, huge HOME API rewrite, release publication/checksum enforcement without pipeline. All violate YAGNI/KISS or exceed authorized scope.

## Milestone 3: Provisioning guard, safe home, honest readiness, and CI gates
- Dependencies: M2 (do not widen CI until concurrency contract is green).
- Decided design (no options left open):
  - Safe HOME root: new `pub(crate) fn agent_home() -> anyhow::Result<PathBuf>` in `src/session/paths.rs` returns `PathBuf::from(HOME)` when `HOME` is set and non-blank after trim, else `bail!("HOME is unset or empty; set HOME to a writable private directory (e.g. export HOME=$PWD/.agent-home)")`. No `/tmp` fallback anywhere. All six roots route through it and become `Result`-propagating (breaking signature change, authorized as valuable): `sessions_dir()`, `endpoint_locks_dir()` (`src/session/locks.rs:169`), `adapter_dir()`, `python_dir()`, `node_dir()`, `browser_dir()` (`src/bridge.rs:113,171,300,385`); derived `venv_python()` (`bridge.rs:179`) and `node_modules_dir()` (`bridge.rs:310`) become `Result`-propagating callers too — update all ~21 direct plus downstream call sites (`spawn_lifecycle.rs`, `close_status.rs`, `doctor.rs`, `bridge.rs` internals) to propagate `?` with context. Decided `doctor` behavior: top-level actionable HOME error (not a partial payload) — if `agent_home()` fails, `doctor()` returns that actionable error immediately. Tests never rely on the fallback: they use the existing `*_in(dir)` / `endpoint_locks_dir_for(root)` seams with `temp_dir()` isolated roots.
  - Adapter symlink policy: before any `create_dir_all`/`write`/`javac`/`npm`/`venv`, `symlink_metadata` the adapter dir and the bridge dest file — this lstat runs BEFORE `file_matches`/`read_to_string` (which would follow a link). Symlink → bail (`must not be a symlink`); existing non-dir/non-file → bail; only then `create_dir_all` the parent (whose parent chain under `agent_home/.agent-debugger` was verified the same way). Bridge writes keep the `file_matches` stale-check after the lstat, then write via an exclusive unique tmp file in the same dir (`create_new`, e.g. `<dest>.tmp.<pid>.<nonce>`, never a fixed name) + atomic rename, with tmp cleanup on failure (never touching the dest or any lock inode). Provisioning never `remove_dir_all` an adapter dir and never deletes a `.lock` file; only its own tmp files. TOCTOU between check and use is documented best-effort (same stance as `check_dir_real`/`real_dir_for_delete`).
  - Provisioning lock scope: four persistent lock files under `<agent_home>/.agent-debugger/adapters/`: `python.lock` (guards `ensure_py` + `ensure_pybridge_in`), `node.lock` (guards `ensure_ws` + `ensure_nodebridge_in` + `ensure_js_shared(node_dir)`), `java.lock` (guards `ensure_compiled`), `browser.lock` (guards `ensure_browserbridge_in` + `ensure_js_shared(browser_dir)`). Browser depends on node `ws` via `NODE_PATH`. Deadlock fix (decided): split each ensure into a non-acquiring `*_locked` inner that assumes its lock is already held (`ensure_ws_locked`, `ensure_nodebridge_locked`, `ensure_browserbridge_locked`, plus `ensure_py_locked`/`ensure_compiled_locked` for symmetry) plus thin public wrappers that acquire once. `ensure_ws()`/`ensure_nodebridge()` acquire only `node.lock` then call their `_locked` inner; `ensure_browserbridge()` acquires `node.lock` then `browser.lock` in fixed order (never reverse) then calls `ensure_ws_locked` + `ensure_browserbridge_locked` — it never calls the locking `ensure_ws()` wrapper while holding `node.lock`. ## Risks and Rollback
- Py lock fix deadlocks or slows pump (gate held across wait) → mitigate by the decided discipline (never hold `_gate` across `select`/pump wait, `_gate→mu` order); rollback is scoped revert of `pybridge.py` gate/pump hunks only + keep repro test as failing marker.
- Java lock move introduces close/teardown race (`closing` check-then-act) → mitigate via `closeFromConn` check-and-set already outside pool + saturation test with exact-close-under-load; rollback is scoped revert of the `serveOverload` call-site hunk only.
- Strict framing breaks lenient client (allowed breaking) → mitigate via shared fixtures + clear `bad Content-Length` errors; rollback is per-language parser revert, not full milestone.
- Provisioning guard wedges on crash/stale FS → mitigate by crash-safe OS `try_lock` (no mtime steal) + 200s bound + retryable error; rollback is scoped code revert only — never `rm adapters/*.lock` or `rm -rf ~/.agent-debugger` while any holder may exist (deletion would break the shared inode rendezvous and admit two holders). Wedged recovery is process exit (OS releases) + retry.
- HOME fail-closed breaks `/tmp`-dependent users (allowed if valuable) → mitigate with the decided actionable `HOME` error + override docs; rollback is scoped revert of the `agent_home()` hunks only (no silent fallback reintroduced without review).
- CI live/flaky (browser/chrome, daemon timing) → mitigate by gating CI to `--unit` only, documenting `--live` for local/release; no retry of deterministic failures, only transient per `cicd-pipeline`.
- No data migration; session/adapter state rollback is dir-preserving (M1) + idempotent reprovision on next `ensure_*` (M3). No releases, no commits, no installs during implementation. No test ever touches the real `~/.agent-debugger` (isolated roots only).
